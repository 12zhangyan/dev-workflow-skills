# 只读代码审查

## 目标与权限

找出会影响正确性、业务语义、数据、安全、并发、兼容或验证有效性的真实问题，并让结论可复核。不得修改代码、测试、正式文档、VCS 或数据库；用户明确要求同步既有交付档案时，仅可按“发布”一节写看板元数据。

## 自主审查

从用户输入、当前对话和 Brief 推断目标与范围；同会话刚完成的实现默认审其实际 changed 文件和 diff，不机械追问入口。只有方案时审方案并说明未审实现；关键入口无法定位时，交互运行只问阻塞问题，非交互返回材料缺口。

先界定应审范围，再按风险决定读取顺序和适用规则。多文件、分批或中断审查时，维护能对回原范围的轻量覆盖记录：已审、按规则排除、失败、待审；按文件或可独立判断的行为分组，排除项说明依据。生成物、vendor 或大文件不因名称自动排除；规则按文件归属、语言和变更行为选择，不加载无关规则全集。

Agent 按风险决定读取顺序和审查视角：

- 找到每个变更文件最近的 Git/SVN owner，按请求区分分支提交与当前工作区；工作区审查包含暂存、未暂存及范围内未跟踪文件，不能用分支差异代替。核对 status 和实际 diff；命令失败保留错误，不能把空结果当 clean。
- 需求符合性：以用户已确认目标、契约或验收为依据，检查遗漏、越界和解释偏差；没有独立需求来源时说明无法判定这部分，继续有依据的实现审查，不从实现反推需求，也不为补齐模板强制提问。
- 实现风险：读取相关实现、调用方、测试与项目规则，检查正确性及适用规范。新增状态、枚举或放宽输入时追踪相关未改消费者，核对过滤、默认分支与序列化；只有证据指向时才扩大范围。
- 对候选问题追踪具体触发路径，并检查足以推翻结论的调用方约束、校验、隔离或框架保证；确认防护覆盖实际路径，不能仅凭危险写法报错，也不能因一条路径安全就排除其他入口。测试通过本身不能替代路径证据。
- 检查验证是否真的执行并断言目标行为：mock 依赖不等于验证真实 SQL/远端；mock 目标逻辑、只断言 mock 返回值或只有 happy path，不能证明被跳过的规则。先核对已有间接覆盖再报缺失，测试数量或覆盖率不代替行为证据；默认 CI 依赖不可控外部服务不能用假凭据换取通过。

审查维度或格式仍不足时读取 [补充参考](reference.md)。需要处理冲突时读取 [交互策略](../../../_shared/interaction-policy.md)，需要解释 Gate 口径时读取 [工作流门禁](../../../_shared/workflow-gates.md)，实际收到或需要交接 Brief 时读取 [Workflow Brief](../../../_shared/workflow-brief.md)。

仅在行为回归的断言或覆盖设计有缺口时读取 [行为测试](../../../_shared/behavioral-testing.md)；仅在后端技术语义影响验证结论时读取 [后端专项](../../../_shared/backend-verification.md)；仅在页面交互或持久化验收有缺口时读取 [浏览器验收](../../../_shared/browser-verification.md)。按实际缺口选读，不联读。本模式仍保持只读。

提示词超限、工具超时、读取截断或子任务失败时，记录具体未完成单元和原因；可缩小批次或定向补读，但不得静默跳过。保留已完成单元的证据和 findings。未覆盖范围补齐前，只报告部分结果，不给整个请求范围通过；全部未完成时明确审查失败。零 findings 只表示没有已证实问题，不证明审查完成。

## Findings

Accepted finding 表示问题已证实，使用稳定 `CR-n / IM-n / MI-n`（首次编号分别对应 Critical / Important / Minor；复审保留原 ID，另记严重度变化），必须包含定位、实际证据和可观察影响。输出前对照本轮文件版本核实路径与行号，删除代码标原侧，行号不可验证时用符号/片段定位，不猜行号。修复方向与验证建议仅在有把握时补充；修法或验证设计未定不撤销 finding，也不代表已具备修复条件。严重度按已证实的触发条件和实际影响判断；影响严重但可达性未证实时保留待验证项。推测、纯风格偏好或证据不足不冒充 finding。

需求符合性与实现风险分别交代证据和缺口，一方通过不代表另一方通过；可用一句话表达，不强制双表或多 reviewer。纯规范建议只有违反适用规则且有实际影响时才进入 finding。

材料足够且没有问题时，只说明“在已检查范围内未发现有证据的问题”及覆盖边界；关键材料不足时列出缺口和受影响结论，不写成通过。测试只报告实际命令、结果和证明边界；状态标签及外部依赖分类仅在有助于交接、门禁或失败归因时使用。

## 输出

作为 loop/package 内部 reviewer 时只返回证据，由协调者决定是否按根入口规则发布。最终答复先给结论和最高优先级问题，再给必要的范围、VCS、验证与未决风险。没有 finding 时不输出空分组，下一动作只在仍有缺口或用户需要继续时给出。
