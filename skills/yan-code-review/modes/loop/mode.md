# Review–Repair Loop

## 目标与边界

用于“审查并在必要时修复”；用户附带的已知 findings 作为首审输入，在首审中核实后沿用原 ID。只读任务用 `check`，只要求修复已有 findings 用 `repair`，需要独立多 reviewer 或外部聚合用 `package`。本模式由单个 Agent 完成审查与修复；高风险修复按下方条件追加一次独立复核，仍不替代 package 的多 reviewer 交叉审查。

不执行数据库写入、DDL、add/commit/push，也不回滚无关改动。涉及业务语义、权限、状态、API/数据契约或数据归属且证据无法裁决时，只阻塞相关 finding；需要提问时读取 [交互策略](../../../_shared/interaction-policy.md)。

## 自主闭环

先用当前规则、代码、Git/SVN status、实际 diff、范围内未跟踪文件和测试证据判断是否有可审实现。没有实现证据时返回材料缺口；未跟踪文件仍可审查和修复，但必须保留纳管风险，不能擅自 add。

有实现证据时读取并执行 [check mode](../check/mode.md)，保持首审零写入。没有 accepted finding 就停止修复；若仍有审查失败或待审范围，继续可行的补证据或报告未完成，不能宣称通过；存在 accepted finding 且在授权范围内时，先读取 [repair mode](../repair/mode.md) 再改任何代码或测试，并按其执行。内部模式按需加载自己的参考，本模式不预加载。

代码变化后补齐受影响的目标验证，再读取最新 status/diff，聚焦复审原问题、相邻风险和测试有效性，按 check mode 的复审格式逐条给出结论；修复 diff 之外的观察记入剩余风险，不作为继续循环的理由。已有修复和证据足以覆盖最终状态、范围内无未闭合问题时结束；不为寻找新工作重启全量审查或增设收尾审计。已确认的验收条件保持有效，不得为结束循环删除必要检查、放宽断言或把失败改成不适用。Agent 可按新证据继续修复、拆分 blocker、调整测试或停止；不设为了流程完整而必须跑满的轮次。出现以下任一条件即停止受影响路径：

- 没有新证据或连续动作没有实质进展；
- 需要新的业务裁决、权限或明显扩大范围；
- 验证环境无法继续且没有安全替代证据；
- 剩余收益低于继续改动引入的风险。

需要解释 VCS、验证或 Gate 结论时才读取 [工作流门禁](../../../_shared/workflow-gates.md)。测试契约失败不能伪装成环境阻塞，也不能用假凭据换取通过。

## 高风险修复的独立复核

修复关闭了 Critical/Important finding，或改动触及权限、状态、数据、并发、公共 API/数据契约时，在最终验证之后追加一次独立复核。宿主可委派时，派一个未参与本轮审查与修复的只读 reviewer：只提供原 finding、最终 diff、验证命令与结果和适用项目规则，不提供修复者的推理或结论，也不写“不要报”“最多算 Minor”这类对 finding 的预判；要求按 [check mode](../check/mode.md) 口径独立返回，核对修复是否覆盖原触发路径、相邻风险与测试有效性。复核者不改代码、不写看板。

复核返回的新问题经核实后按同一编号序列接续，回到本 loop 处理；修复被驳回时，优先补齐缺失证据或换一个 Agent 修复，不让原修复者凭原有理解反复重试。宿主不可委派（包括宿主规则要求用户明确授权才能派发子智能体而本次未获授权）、委派失败或没有可用独立视角时，以验证证据关闭并标为自验证关闭，不称独立复核通过，并告知用户可明确授权派发复核或改用 package 获取独立 reviewer。只有 Minor 修复或没有代码变化时不派发。

## 完成与交接

finding ID 在审查、修复和复审间保持稳定；关闭前读取 [工作流门禁](../../../_shared/workflow-gates.md) 的“声明与证据”表并逐条对照，只有最新实现与验证证据都支持时才关闭。未关闭 Critical/Important、验证未满足用户验收要求或关键文件未纳管时，不宣称 Review/Submit 通过。

默认在聊天中简洁报告实际审查范围、findings 状态、修改、验证、独立复核结果或自验证关闭、VCS/未跟踪边界和剩余风险。只有用户要求持久审计格式或表达仍歧义时读取 [回执参考](reference.md)。无代码变化无需机械复审；未运行测试不是 finding，但可能意味着用户目标尚未完成。

真实跨 Agent、跨任务或延期恢复时才读取 [Workflow Brief](../../../_shared/workflow-brief.md)。仅在需要消除“单/多 Agent”歧义或供机器消费时输出 `ReviewAgentMode: SingleAgentReview` 等标签；不强制固定回执字段、修复轮次数或“唯一下一动作”。
