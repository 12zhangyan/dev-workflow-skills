# Incident document reference

只在准备生成持久事故文档时读取。以下结构按证据与读者需要裁剪，不是固定七节流程。

```markdown
# <故障标题> 事故记录

> 状态：调查中 / 根因已证实 / 等待验证 / 已关闭
> 发生范围与版本：...
> 关键证据：日志、请求、数据、代码、构建或部署位置

## 现象与影响
- 期望 / 实际：...
- 影响对象、时间范围、频率与绕行方式：...
- 复现状态与触发条件：...

## 证据链与根因状态
| 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|
| ... | ... | ... |

- 已证实事实：...
- 根因或候选假设：...
- 已排除解释：...
- 版本漂移 / 待确认：...

## 下一动作
[根因未证实：能区分假设的最小诊断动作]
[根因已证实：最小修复边界、禁止改动、回归风险和可观察验证]

## 验收证据
- 命令/操作与结果：...
- 尚未覆盖：...
```

严重度只在影响当前优先级时记录，不机械套 P0-P3。修复建议必须与已证实机制相连；根因未证实时不得生成执行型 changeList/todos。

仅在已授权发布看板时读取 [共享看板发布流程](../../../_shared/board-publish-flow.md)。条目先写入 `project-html/data/_entry.json`，再交给 `board-add.js`；禁止手工插入标记行或整体重写 `data/changes.js`。
