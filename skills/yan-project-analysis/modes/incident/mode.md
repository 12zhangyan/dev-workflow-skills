# Incident mode

## 目标与边界

沉淀可复核的单次故障记录：现象、影响、触发、证据、根因强度和下一动作。默认写入 `docs/bugs/<日期>/<任务>.md`；不修改业务代码，不把一般 review 或产品改造包装成事故。看板仅按明确要求以 `kind:"bug"` 发布。

## 成功标准

- 现象、影响、复现状态和触发条件可定位来源；日志出现不等于完整业务成功。
- 根因有从现象到机制的证据链，并记录替代解释、版本漂移和缺口。
- 根因未证实时只给能区分假设的诊断动作；已证实时给最小修复边界、回归风险和可观察验收。
- 接手者能判断结论强度并执行当前最有价值的下一动作。

## 自主调查

从对话、日志/堆栈、请求路径、复现、监控、版本、VCS 和代码入口中选择能裁决竞争假设的证据，不固定目录深度或调用层数。互不依赖的日志关联、版本核验、代码机制和数据现象可并行委派；一个整合者按同一时间窗和版本归并，冲突不投票消解。

区分源码、构建产物、部署包和实际运行证据。现场与 checkout 不一致时记录版本漂移，不能用本地源码覆盖事故现场。数据库只读，查询只证明实际覆盖的事实。

只有严重度、业务语义、权限、数据归属、修复边界或文件覆盖会改变结论时，才读取 [交互策略](../../../_shared/interaction-policy.md)。非交互/无人值守运行中不等待提问：缺少任务入口、关键现场证据或安全写入路径时输出 `Blocked` 和最小补充项，不写 Bug 文档、看板或执行型修复 Todo。

## 产物与可选发布

准备写事故文档时才读取 [自适应模板](reference.md)。

用 [workflow-fs.js](../../../_shared/scripts/workflow-fs.js) 创建日期目录并检查 `file-state`；已存在、不可读或状态未知时不静默覆盖，无人值守时停止写入。

需要看板时才读取并严格执行 [共享看板发布流程](../../../_shared/board-publish-flow.md)。Agent 专属字段禁止写入看板 entry；只保留面向同事的现象、影响、根因强度、修复边界和验收结果，并只通过 `board-add.js` 写入。

存在真实跨 Agent、跨任务或延期恢复时才读取 [Workflow Brief](../../../_shared/workflow-brief.md)，主文档只保留一份索引，聊天不重复。其余完成信息按实际结果裁剪，不输出无关状态占位。

## 硬边界

- 不执行数据库写入、DDL、数据修复、add、commit 或 push；不回显凭据或敏感值。
- 不把推断写成根因、未运行验证写成通过、源码存在写成已部署修复。
- 冲突未裁决时保留各方证据和影响，不替用户选择业务口径。
