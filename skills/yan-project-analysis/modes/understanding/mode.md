# Understanding mode

## 目标与模式

只解释代码实际如何工作以及契约变化会影响什么，不判断 Bug、不关闭 findings、不输出修复方案。

- `ImpactAnalysis`：用户要影响、兼容性或调用方结论时使用；聊天交付，`WritePolicy: NoWorkspaceWrites`。
- `CodeMap`：用户明确要代码地图、调用链文档或持久化阅读材料时使用；写入 `docs/code-reading/<日期>/<功能名>.md`。

意图不清时选择副作用更小的 `ImpactAnalysis`。只有是否落盘会实质改变用户目标时才读取 [交互策略](../../../_shared/interaction-policy.md) 并问一个问题。非交互/无人值守运行中不等待提问；关键入口多解且会改变结论或写入范围时输出 `Blocked` 和候选证据。

`ImpactAnalysis` 是严格仓库零写入模式：禁止修改工作区、文档、看板、VCS 或业务系统。宿主为读取 PDF 等材料而在仓库外创建的受控临时产物不算交付物，不得包含或泄露敏感内容；用户要求绝对零写入时也不得创建这类临时产物。

## 成功标准

- 从最可信入口追踪到足以解释目标行为、状态、副作用或契约边界，结论附文件/行号、契约页码或其他可复核位置。
- 追踪深度由证据充分性决定；遇到动态分派、跨服务或不可见实现时明确未展开边界。
- `ImpactAnalysis` 把相关对象分为“明确受影响 / 证据显示不受影响 / 待确认”，只展开会改变结论的契约维度。
- `CodeMap` 给读者入口、主调用链、状态/副作用、关键位置和必要的方案对照；表示法按复杂度选择。
- 材料不足时说明缺口，不凭文件名、排序或相似类猜调用链。

## 自主取证

把用户目标、明确路径/符号、Brief、已有文档、当前 VCS 改动和搜索候选视为同一组入口证据，由 Agent 选择最可信起点。Brief 是索引，不是真相；章节名和文件顺序只能作兼容提示。优先读取能裁决结论的文件，再按证据缺口扩展，不设固定文件数、追踪层数或变量读写次数。

关注与目标相关的调用、状态变化、事务/并发机制、异常分支、数据库/缓存/MQ/外部调用和可观察结果。契约分析按实际变化检查 method/path、请求、响应、错误行为、鉴权和副作用；异步、流式或队列场景再按证据补断连、重试、顺序、幂等和最终一致性。

输入材料不可读时列为 blocker；数据库只读。不得自动 add、commit 或 push。

## 交付与可选写入

`ImpactAnalysis` 在形成结论时才读取 [输出契约](impact-output.md)，直接回复，不生成 md、看板、单页或索引。只有确有跨任务下一动作时才读取 [Workflow Brief](../../../_shared/workflow-brief.md) 并附精简索引；否则不为填字段制造 Brief。

`CodeMap` 在准备落盘时才读取 [文档模板](codemap-template.md)。先以当前 mode 目录解析 [workflow-fs.js](../../../_shared/scripts/workflow-fs.js) 的绝对路径，用它创建路径并执行 `file-state`；已存在、不可读或状态未知时不得静默覆盖。需要处理冲突时读取交互策略；无人值守则停止写入并报告 blocker。

看板不是隐含副作用。仅在用户明确要求登记看板，或输入 Brief 明确要求同步同一交付档案时，才读取并执行 [共享看板发布流程](../../../_shared/board-publish-flow.md)，以 `kind:"reading"` 发布。只能通过 `board-add.js` 写入，禁止手工编辑 `data/changes.js`。发布失败不否定已经安全生成的代码地图。

完成时说明所选分析方式、证据范围、实际产物或零写入结果、未决边界和有价值的下一动作。只有看板实际参与时才报告其结果；CodeMap 的 Brief 只在主文档保留一份，聊天不重复。
