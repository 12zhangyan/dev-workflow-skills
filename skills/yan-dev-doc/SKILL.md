# Yan Dev Doc

## 目标

把需要先评审的需求写成 `docs/<日期>/<任务>.md`。让后续 Agent 依据事实、硬边界和验收结果自主实施。

本 Skill 只形成方案，不实现业务代码，不执行数据库写入，不自动 add、commit 或 push。默认产物是主方案和同一交付的看板档案；OpenAPI 和 Workflow Brief 按实际需要生成。本 Skill 自包含运行，不依赖任何外部 Skill 或方法论。

## 完成标准

接手方能从方案判断要改变什么、哪些边界必须保持、每个结果如何验收，以及哪些决策仍缺证据。事实与假设可追溯，计划、构建和实际运行证据分开；只保留适用内容。执行 Agent 可合并、细分、重排或委派非约束性切片。

## 执行

### 收集足以决策的证据

读取用户指定材料、当前目录生效的项目规则和与决策相关的代码、契约、配置、diff、日志或测试。围绕入口、业务规则、状态/权限、数据归属、副作用、兼容与验收补证据；不设固定读取深度、文件数或问题数。

能从证据判断的内容直接采用。低风险未知写明依据和可修订边界；高风险未知只阻塞受影响部分。任务仍可识别时生成 `NeedsConfirmation` 草稿，保留已确认结论和可独立推进的切片，但不为未知部分编造接口、权限、数据口径或可执行写操作。任务或安全写入目标本身无法识别时不落盘。

仅在阻塞型未知或证据冲突需要用户裁决时读取 [交互协议](../_shared/interaction-policy.md)；仅在工具、终端或路径行为存在宿主差异时读取 [宿主能力](../_shared/host-capabilities.md)。

### 形成方案

按任务复杂度选择短篇、展开或增量表达，覆盖适用内容：

- 目标、范围、非目标、不可改行为和总体验收；涉及权限、状态或副作用时，验收同时说明应发生的结果与必须保持的拒绝、隔离或不执行行为；
- 关键证据、决策理由、低风险假设、已裁决冲突和仍开放的问题；
- 面向可观察结果的工作切片，包括范围、硬边界、真实依赖、完成判据和验证证据；跨层功能优先用一条最小完整业务路径检验契约与集成风险，避免只按 Controller/Service/Mapper 层分批完成后才集成；
- 适用的兼容、事务、并发、错误路径、发布、回滚及未覆盖风险。

需要用图解释组件、调用、数据或状态关系时，才读取 [图表与证据](../_shared/diagram-evidence.md)。

机械迁移、共享接口变更等无法独立验收的改动可按兼容阶段组织，保留最终集成验证点；小改动无需强拆。增量修订只写相对可读前置方案的变化和继续有效的约束。只有硬边界、业务口径或验收标准的变化需要回到方案确认；普通实现细节、工具、切片组织和角色分配由执行 Agent 决定。

仅在行为回归的断言或覆盖设计有缺口时读取 [行为测试](../_shared/behavioral-testing.md)；仅在后端技术语义影响验证结论时读取 [后端专项](../_shared/backend-verification.md)；仅在页面交互或持久化验收有缺口时读取 [浏览器验收](../_shared/browser-verification.md)。按实际缺口选读，不联读。方案阶段仅设计验证，不执行测试或业务操作。

### 写入与条件产物

写入主方案前才读取 [方案骨架](plan-template.md) 并按任务裁剪；执行卡片、工作切片和验收矩阵让执行 Agent 不必通读全文即可开工。

用 [workflow-fs.js](../_shared/scripts/workflow-fs.js) 创建日期目录并检查目标 `file-state`。已授权更新时先读后改，保留任务外内容，不重复确认；默认名称冲突且未锁定路径时选稳定后缀，重新检查后写入并报告实际路径。目标不可读、状态未知，或精确路径冲突且未获修改授权时停止受影响写入。只修改本任务产物。

新增接口或请求/响应/鉴权/错误语义发生契约变化时，才读取 [OpenAPI 发布协议](publishing-openapi.md)。纯行为变化或仅调用既有接口不重写规范。

主方案实际落盘后才读取 [看板发布协议](publishing-board.md)，默认创建或续写同一交付档案；项目尚无 `project-html` 时由协议初始化。用户明确不要看板或只要聊天输出，或主方案未安全写入时，不初始化或修改 `project-html`。

只有真实跨 Agent、跨任务或稍后恢复时，才读取 [Workflow Brief](../_shared/workflow-brief.md) 并在持久产物中保留一份。当前 Agent 能继续或任务已结束时不制造交接块。

## 不可越过的边界

- 数据库保持只读。DDL/DML 只能作为供用户或 DBA 审批的建议，附回滚和只读核验；数据更新必须有主键或唯一约束证据，证据不足保持 `NeedsConfirmation`。
- 按实际文件定位 Git/SVN owner；只有归属、基线或变更来源影响方案时读取历史。Maven 验证必须基于真实 reactor/POM 关系，不能假设 `-pl/-am` 可跨 reactor。
- 未经明确授权不 add、commit、push、覆盖文件、发送外部内容或执行其他不可逆动作。敏感信息只记录位置、类型和风险，不回显值。

## 交付

报告实际文档与条件产物路径、`Passed | NeedsConfirmation | EnvironmentBlocked`、关键未决项、验证设计和当前最小下一动作。只声称本轮证据真实证明的结果；生成方案不等于功能已经实现或验证。
