# Yan Dev Doc plan template

只在写入主方案前读取。这是可裁剪骨架，不是固定章节清单：Compact 任务可只保留执行卡片、验收矩阵和证据边界；不适用的节整节删除，不留空标题或“无”。

````markdown
# <任务名> 开发方案

> 交付：方案已生成，未实施
> 决策状态：可评审 / 方案待确认（NeedsConfirmation，见“待裁决”）/ 环境阻塞（EnvironmentBlocked）
> 日期与来源：<YYYY-MM-DD>；<需求、Issue、对话或前置方案路径>
> 实施边界：<执行 Agent 可修改的模块/目录>；数据库只读；不 add / commit / push

## 执行卡片
- 要改变的结果：<一句话，可观察>
- 必须保持：<不可改的行为、契约、权限/隔离与兼容边界>
- 开工前先核验：<最能证伪本方案的文件或命令；与方案不符时先停下报告差异>
- 建议首个切片：<一条最小完整业务路径>
- 整体完成判据：<哪组命令或验收场景证明全部完成>

## 背景与目标
- 背景：<为什么做；引用证据位置>
- 目标：<可观察结果>
- 非目标：<明确不做>

## 证据与决策
| 结论 | 证据（路径:行 / 命令 / 文档） | 类型 |
|---|---|---|
| <事实或决策> | <位置> | 已证实 / 低风险假设 / 用户已裁决 |
| <被否决的替代方案：否决理由；会推翻当前选择的前提> | <位置> | 已否决替代（仅在存在真实替代时保留此行） |

## 方案
<总体流程、关键数据/状态流和重要取舍；需要时附 Mermaid。只写约束实现的设计，类/方法级细节由执行 Agent 决定。>

## 工作切片
| 切片 | 可观察结果 | 改动范围 | 硬边界 | 依赖 | 完成判据与验证 |
|---|---|---|---|---|---|
| S1 | <行为> | <模块、包或文件> | <禁止改动> | <前置切片/外部条件> | <测试名或命令 + 预期结果> |

切片顺序与粒度是建议；执行 Agent 可合并、细分、重排或并行委派，但不得越过硬边界。

## 验收矩阵
| 场景 | 前置与输入 | 期望结果 | 必须保持的拒绝 / 隔离 / 不执行 | 验证方式 |
|---|---|---|---|---|

## 兼容、风险与回滚
<仅适用时：数据迁移、事务/并发、错误路径、发布顺序、回滚方式和未覆盖风险>

## 待裁决
| ID | 问题 | 证据冲突或缺口 | 影响的切片 | 裁决前可继续的部分 |
|---|---|---|---|---|

## 证据边界
- 已证实：...
- 假设（可修订边界）：...
- 计划中的验证（尚未运行）：...
````

填写要求：

- 路径、类名和命令按真实仓库填写；无法确认时写入“待裁决”或“假设”，不编造占位路径。
- 每个切片的验证能单独运行，并说明预期结果；只依赖外部环境的验证标明前置条件。
- DDL/DML 只作为待审批建议，附回滚与只读核验。
- 不复制看板叙述；看板由发布协议另行面向人类撰写。
