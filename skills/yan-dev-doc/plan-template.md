# Yan Dev Doc plan template

只在写入主方案前读取。先按任务选骨架，再删去不适用的节；不留空标题、“无”或“无阻塞项”。

## 书写规则

- 每个事实只写一次：证据与决策表是事实、假设和替代方案的唯一出处，其他节用 `E-n` 引用，不复述。
- 编号稳定：证据 `E-n`、切片 `S-n`、验收 `A-n`、待裁决 `Q-n`；修订时沿用旧编号，删除的编号不复用，供 Review 与看板引用。
- 实现方式、切片组织等由 Agent 定下而用户未确认的取舍，在证据表标为“Agent 代决”并写错了的代价；会改变业务口径、权限或接口契约的问题进入待裁决。
- 低风险假设只在证据表标为“假设”并写推翻条件；只有会阻塞切片或需要用户裁决的才进入待裁决。
- 仓库默认边界（数据库只读、不 add/commit/push）不在每份方案重复；只写本任务额外的限制或例外。
- 切片只覆盖执行 Agent 要交付的代码、测试和调用方改动；OpenAPI、索引、看板等由本 Skill 同步的附属产物不作为切片。
- 路径、类名和命令按真实仓库填写；无法确认就标为假设或待裁决，不编造占位路径。

增量修订在标题下加一行 `> 修订：<日期> 相对 <前置方案路径或修订> 的变化`，只写变化和继续有效的约束。DDL/DML 只作为待审批建议，附回滚与只读核验。不复制看板叙述；看板由发布协议另行面向人类撰写。
