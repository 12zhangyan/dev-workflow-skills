# 后端专项验证参考

仅选择当前风险涉及的技术层。先从构建配置、已有代码和维护中的业务契约确认 JDK、框架、数据库方言、术语及状态含义；外部专家模板不能替项目升级版本或裁决业务语义。存在冲突时记录来源及影响，不默认新建术语表或大规模技术改造。

| 当前风险 | 有判别力的核验 | 证明边界 |
|---|---|---|
| SQL / Mapper | 对照真实映射与参数，关注归属条件、筛选与分页顺序、total、稳定排序及相关空值/排序规则；需要运行时证据时使用相同方言和相关 schema 的只读查询或已有集成证据 | repository stub 只证明调用或结果处理；内存实现与不同方言的测试不能证明目标 SQL；EXPLAIN 估计不等于实测性能 |
| 事务 / 异步 | 沿实际调用入口核对代理、事务管理器、异常传播及消息/远端副作用边界；只在相关风险存在时补失败路径证据 | 注解存在不等于事务已生效，数据库回滚不等于外部消息撤回；请求被受理不等于消费完成 |
| 幂等 / 并发 | 对照幂等键的业务范围、数据库约束和实际竞争窗口，区分同时到达、超时重试与重复消费 | 一次成功或顺序重放不证明并发安全；仅凭某行代码缺锁也不能排除其他有效防护 |
| API / 权限 / 状态 | 经实际入口核对鉴权、对象归属、状态前置条件和错误语义；使用项目已确认的名词与状态转换 | UI 隐藏按钮不证明服务端拒绝；单入口防护不代表全部入口；不能凭字段名推断业务口径 |

验证强度由真实风险与已有证据决定，不因项目使用 Java 或 SQL 就执行整张表。运行前确认命令是否启动服务、迁移或写库；当前模式的数据库只读边界不因“测试”而改变。需要建表、造数或数据修复时只记录验证缺口，交给另行获授权且项目允许的流程。缺少相应证据应限制结论，不自动认定实现有缺陷。
