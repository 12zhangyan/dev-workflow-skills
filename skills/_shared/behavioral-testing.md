# 行为测试参考

用于设计或审查有实际缺口的行为回归。选择能区分正确实现与候选错误的少量用例；已有间接覆盖足够时不重复补测，也不要求统一测试比例或固定 TDD 顺序。

## 让断言有独立依据

从已确认契约、可手算例子或独立不变量取得期望值，经真实对外入口观察结果。避免调用被测函数、复用被测常量或照抄同一算法来计算 expected；那样实现与断言可能一起出错。性质测试仍可使用独立业务不变量，无需全部改成字面量。存在项目术语表或 ADR 时沿用其已确认语义，未知规则不由测试作者补造。

例如已确认折扣为 10%，输入 100 的应付金额应为 90；从实现导出的 DISCOUNT_RATE 再算一遍期望金额，不能检出该常量误改为 15%。

## 选能裁决问题的输入

按变更选取边界、拒绝路径、状态转换或副作用，说明每项能抓住什么错误：分页同时观察页内容与筛选后总量；隔离规则使用会混入其他归属数据的样本；失败路径核对禁止发生的消息或写入。幂等与并发不是同一结论，顺序重试测试不能证明竞争请求安全。无需把这些例子全套用于每个改动。

若问题涉及异步状态归属，用可控的延迟响应验证页面离开、记录或会话切换后的完成顺序；按风险分别观察迟到成功、失败和清理回调，旧请求不能改写新上下文、触发跳转或带着新身份重试。测试保留真实的路由或状态宿主，只替换外部边界；夹具提前销毁宿主造成的失败不算业务复现。

mock 可隔离非目标依赖，但断言仍应约束被测行为；真实 SQL、框架代理或远端结果需要相应层的证据。已存在从调用方进入目标逻辑的覆盖也有效，不按测试文件名或数量认定缺失。

## 验证回归是否敏感

已有实现可直接补回归，不为追求先红后绿删除或重写用户已有工作。高风险且用例是否有效存疑时，可在隔离副本用旧实现或已知错误实现检查能否失败，并核对失败是否来自目标断言；语法错误或环境启动失败不能证明测试有效。这是可选取证方法，不是每次必须做变异测试。
