里面具体写什么？

这五个模板对应 Skill 的实际产物阶段。它们共用同一任务编号，但各自回答不同问题：方案讲“为什么与怎么做”，审查讲“证据与问题”，修复讲“哪些 finding 关闭了”，闭环讲“整个 Review Gate 最终是否通过”。

SELECT RECORD TYPE

拍板时只需要回答一件事你希望团队首先看到的是“一个任务的完整故事”、 “两类产物的独立责任”，还是“交付 Gate 是否通过”？
A · 一事一档

阅读成本最低；数据合并最深。适合需求量中等、希望业务和研发共读。

B · 双轨泳道

审计最清楚；记录数量更多。适合多轮 Review、多 AI 或多人协作。

C · Gate 驾驶舱

流程状态最醒目；需要维护 gate 事件。适合重流程、强交付治理。

选择方式示例：“选 A，但我想保留 B 的独立审查编号” / “选 C，颜色改成现在看板的纸面风格”。拍板前不会修改 project-html/ 正式外壳、board-add.js 或 Skill 写入规则。
